# Scope of native capture evidence

The user selects the root model and reasoning effort; Antigravity siblings inherit both by default. The user directly tested that host behavior, and MathTrace treats it as resolved. MathTrace performs no automatic routing, downgrade, upgrade or override of either setting. Users may manually change an agent's configuration for a different subagent model. Recorder metadata need not expose effort for this policy to hold; tool/state/context-access qualification is a separate boundary.

Canonical recovery remains available when a parent transcript, host database or current role file disappears. It preserves the original terminal evidence and exposes any retained unresolved conflicts; it never retries. Changed present inputs or broken attribution still require investigation and do not become protocol failures.

`capture_native` observes local Antigravity CLI producer records for the specified child and its recorded parent dispatch. It checks the requested role type and model/workspace arguments, exact packet and child input, and the response in the captured public task interval. It also checks that the currently installed local role file matches the owned renderer.

These observations are distinct from effective host configuration:

| Recorded field | Meaning |
|---|---|
| `requested_role_type` / `parent_dispatch.requested_type` | The role name present in the observed native dispatch |
| `installed_role_definition_hash` | Hash of the currently installed file checked by the recorder |
| `host_instantiated_role_definition_hash: null` | The producer evidence does not establish which exact role-definition bytes the host instantiated |
| `declared_tools` / `declared_inherited_history` | The workflow's requested policy, not effective capability measurements |
| `effective_host_tool_policy: null` | Effective hidden host capabilities are not determined by this capture |
| `complete_host_context_observed: false` | The public transcript is not a complete inventory of hidden host context |
| `unaccounted_public_event_count` | Additional recorded public events that trigger an exposure record and prevent blind-review qualification |

The operational review label `independent` retains its provenance scope `observed-public-task-context`. New qualified captures additionally bind `agy-1.2.16-recorded-input-no-tools-v1`: exact producer-recorded inputs and no recorded tool use. It is not a claim of statistically independent errors, complete absence of hidden instructions, or cryptographic host attestation. Capture explicitly states that effective host isolation was not verified. Residual controls remain callable; dispatcher/OS denial is unprovided, rather than implied by schema omission.

Before collecting a new result for independent use, call `inspect_native_context` with the exact task/child. The supported local profile requires one complete stored generator observation, the sole packet input and this run's own public terminal output, exact accounted static system sections/owned role body, the pinned messaging/task schemas and zero initiated producer tool calls in any status. It exports static inputs and the already-public response, excluding generated reasoning. Missing, ambiguous or additional inputs/schemas fail this qualification.

Root reviews the exact operational bootstrap for task-neutral-bootstrap, no-mathematical-history-or-advice and operational-conflicts-assessed, then calls `admit_native_context` with that observation_hash, all three checks and a substantive reason. Benign global platform-guide skills are permitted bootstrap; their mere presence is not contamination. Assess actual task-specific leakage and unauthorized tool/state access. Messaging reminders may conflict with the assigned policy; root assesses recorded compliance. Admission accepts neither mathematics nor source execution. Nonterminal observations can receive admission once the terminal inputs are inspectable. Terminal captures without admission commit an unknown hold atomically; later admission cannot upgrade them. Withdrawal or a finding against admission/terminal-capture evidence invalidates dependent qualification, including informed adjudication. Current host-file loss or withdrawal does not erase exact historical replay; changed recorded inputs retain conflict evidence. Role comparison permits only CRLF-to-LF mapping while preserving raw recorded text.

Operator-imported reports remain distinct from producer-recorded capture and cannot satisfy independent-capture gates. Hashes and local paths do not protect against a compromised host or another process able to rewrite producer records; protected execution remains a separate requirement. No tool policy or mathematical proof rule is changed by these terminology clarifications.

## Dispatch and recovery

`reserve_native` takes `tasks` and the actual native `parent` UUID. Its immutable dispatch record stores the complete `invoke_subagent` arguments. Submit the returned `arguments` unchanged once. Reservation is intent only; neither its existence nor absence of a result establishes whether the host is running. `next` includes the dispatch record and parent for allocation recovery. Repeated reservation of the same task is rejected.

Capture joins the child-creation result to the exact dispatch using the producer's call ID. A matching packet in some other call of the same parent cannot qualify a child. Reserved tasks additionally require the intended parent and complete argument array. For a batch, the exact child input must match a unique requested packet; this identifies the requested specification, not the host's hidden instantiated configuration. Duplicate matching specifications fail closed. Historical unreserved capture can still establish observed provenance, but records `dispatch_request: null` and makes no prior-reservation claim.

The allocation schema is based on read-only inspection of an earlier local producer run: completed generic step type 132, call metadata at protobuf path 5/4, public creation output at 140/2/1. This narrow observed profile is not a general vendor schema guarantee. Unknown or ambiguous binding fails closed. R3-H1/H2 exercised actual native allocation, input, capture and qualified mediation/recovery at the recorded-input scope. Fixture tests do not establish host enforcement.

The actual agy1.2.16 probe additionally observed `antigravity-parent-message-v1`: a completed SYSTEM_MESSAGE with an exact known wrapper, timestamp/parent sender/priority and the complete packet JSON. Inspection and capture share the same first-terminal input selector, binding the sender to the actual allocation/call/reservation. Raw USER_INPUT remains the historical `raw-user-input-v1` profile. Duplicate inputs, wrong sender, malformed wrappers, arbitrary embedded JSON and cross-call substitution fail attribution; they are not worker protocol failures. Capture retains the raw row/header/profile. Only that row position is accounted for; other context and postterminal rows remain exposure/conflict evidence. Timestamp is metadata, not proof of overlap or termination.

At the R3-H1 checkpoint, root attached artifact-backed `unknown` exposure to the two original runs before independent use. Those historical holds survive replay/recovery; benign global platform-guide presence is not itself a contamination basis. R3-H2 subsequently inspected exact recorded inputs and implemented the scoped admission above. A fresh qualified reviewer assessed the original proposal, root executed it once in isolation and a new exact native task reviewed its evidence scope. The claim remains unsupported/unreleased, and the original author's hold remains. Self-reports or marker absence alone do not establish enforcement; residual controls and stronger isolation limits remain explicit. The worker protocol states assigned policy rather than claiming capabilities are physically absent.

Use `inspect_native` with `dispatch` to recover child handles when the original tool response was lost. It returns matching call IDs and allocations, matching each child's exact input to its task when available. It flags repeated matching dispatches and leaves unmatched children unassigned. This operation is read-only and never claims terminal status or authorizes retry. Missing databases or incomplete records require another observation, not another dispatch.
