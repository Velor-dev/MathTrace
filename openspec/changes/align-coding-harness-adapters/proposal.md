# Proposal

## Why

The approved 2026-10-21 harness audit found missing Cline static profiles, an archived Kimi product target, and incompatible OpenCode V1/V2 permission dialects. Correct deployment requires native payloads without altering mathematical instructions or overstating host qualification.

## What Changes

- Generate eleven Cline frontmatter-plus-body `.yaml` profiles with empty tool lists for the audited loader contract.
- **BREAKING**: migrate the Kimi Code staging payload from legacy `.kimi` YAML mappings to `.kimi-code` Markdown agents and skills; retire only exact known generated legacy files, preserving modified and external assets.
- Preserve `opencode` as V1; add explicitly selectable `opencode-v2` staging output with plural ordered permissions. Kilo stays on its own singular dialect.
- Restore Devin shared role body identity and refresh all audited compatibility documentation, inheritance caveats and dynamic-provider descriptions.
- Add deterministic generation, preservation and migration regression checks. Keep Antigravity and shared mathematical instructions unchanged.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `native-agent-isolation`: specify deterministic portable staging payloads, exact mathematical body preservation, version-specific permission formats and safe legacy migration without claiming runtime admission.

## Impact

Changes are scoped to `coding-harnesses`, regression tests and OpenSpec artifacts. No runtime ledger, checker, capture backend, host installation, authentication or model routing is added. Existing qualified native operation and all mathematical admission gates remain authoritative. Implementation is explicitly approved by the user against the retained audit report.
