# Design

## Context

See `proposal.md` for motivation. Native operational skills are generated by `mathtrace/native.py::runtime_files()` and installed through `tools/install_native.py`. Each currently reads `.agents/math/PROTOCOL.md`; the guide is already generated at `.agents/math/help.md`.

Other harnesses generally forward through thin wrappers to `coding-harnesses/shared/skills/`, whose intake and progress definitions read the shared protocol. The shared guide already exists beside it. The supported payload inventory lives in `coding-harnesses/research.json`. Codex retains both `.codex/skills` and compatibility `.agents/skills` entry points, paired agent files, and renderer preservation checks.

Antigravity is a frozen native snapshot excluded from ordinary adapter rendering. Its two entry skills and guide live under its `.agents/` payload. Existing snapshot integrity metadata has differences from current generated content, so wholesale regeneration would exceed this change's scope.

## Goals / Non-Goals

**Goals:** Add a small root-agent discovery instruction in maintained definitions; carry equivalent semantics through every supported payload; verify guide resolution and preservation using existing projection tests.

**Non-Goals:** Change guide content, protocol authority, skill mandates, specialist prompts, delegation rules, runtime verification, or harness tool bindings. Add no skills, routing layers, fixed sequences, workflows, installers, or abstractions.

## Decisions

### 1. Add discovery beside the existing protocol instruction

In the native renderer, append a brief guide instruction only for `math-intake` and `math-progress`. Apply equivalent wording in their two shared definitions. Preserve each existing mandate verbatim. The instruction tells the main agent to read the guide directly and select relevant skills when appropriate to the current request and campaign state; the guide does not expand authorization or mandate a sequence.

Use `.agents/math/help.md` in native output and `coding-harnesses/shared/help.md` in shared definitions, interpreted from the target project root. Keep protocol reading intact. Avoid invoking `mathtrace-help`: its display-only behavior serves explicit help requests and is unnecessary for discovery. Adding this requirement to all skills or specialist packets would widen context and scope without improving these entry points.

### 2. Propagate through existing adapter forwarding

Updating the shared definitions reaches supported adapters through their existing wrappers. Verify this against the complete inventory, including both OpenCode variants and externally loaded skills such as Hermes, using the documented deployment with shared assets available in the target project. Unchanged wrapper bytes are acceptable when their forwarding already provides the new behavior.

Keep Codex's two skill locations and paired agent files intact. Preserve its owner-customization checks and known preserved hashes; do not weaken those checks or regenerate unrelated files to deliver a shared-source instruction. No renderer restructuring is needed for wrappers already forwarding correctly.

### 3. Refresh only Antigravity's two affected snapshot skills

Apply the same native discovery addition to the snapshot intake and progress files, preserving their existing bodies. This request explicitly includes Antigravity, making a narrow snapshot refresh appropriate. Leave ordinary rendering's Antigravity exclusion intact. Compare before and after snapshots to ensure unrelated roles, guides, skills, and assets remain unchanged.

Reconcile integrity entries only for the two changed files where the snapshot manifest records them. Preserve unrelated pre-existing manifest differences and historical origin records; do not represent this targeted refresh as a complete snapshot regeneration. A full native install over the frozen snapshot would unnecessarily replace unrelated content.

### 4. Verify instructions and deployed paths deterministically

Extend `tests/test_native.py` for generated entry-point guidance and managed installation. Extend `tests/test_harness_payloads.py` to follow both entry skills across the inventory into an existing guide, exercising project-root path resolution and both Codex locations. Preserve existing repeatability, owner-customization, worker isolation, and Antigravity-freeze checks. Test intended instructions and file resolution; no live host launch or mathematical campaign is needed for this text change.

## Risks / Trade-offs

- Relative paths may be interpreted from a skill directory instead of the deployed project root → explicitly anchor guide references to the project root and test the documented layouts, including external loaders.
- Discovery could imply authorization to continue work → explicitly retain request scope and discretionary selection; verify progress-only requests do not instruct automatic execution.
- Broad regeneration could overwrite Codex customizations or Antigravity history → use the managed native installer, existing adapter preservation rules, and the two-file snapshot refresh with bounded metadata updates.
- Text tests cannot prove every model's future choice of skill → verify the instruction contract and path availability; do not introduce a router to enforce model behavior.

## Migration Plan

Update maintained sources and focused tests, regenerate the managed native projection, and refresh the two Antigravity snapshot entries with applicable integrity metadata. Confirm shared forwarding provides coverage for the full supported inventory, then run repository validation. Existing deployments receive updated payloads and shared assets through their existing installation process; campaign data needs no migration.

Rollback restores the changed source instructions and their generated projections through existing generation/install paths, plus the two snapshot entries and their corresponding integrity entries. No campaign events, evidence, or historical receipts are rewritten.
