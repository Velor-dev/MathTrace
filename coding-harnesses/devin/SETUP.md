# Devin CLI binding

Research date: **2026-10-15**. Targets the local Cognition Devin CLI, not automatic Cloud handoff. Official sources: [CLI setup](https://docs.devin.ai/cli), [subagents](https://docs.devin.ai/cli/subagents), [skills](https://docs.devin.ai/cli/extensibility/skills/overview), [skill schema](https://docs.devin.ai/cli/extensibility/skills/creating-skills), [project rules](https://docs.devin.ai/cli/extensibility/rules).

Install/authenticate through the official guide separately. Merge `.devin/skills/` and `.devin/agents/` into the target root. Keep `coding-harnesses/shared/` and merge [shared project instructions](../shared/project-instructions.md) into the existing root `AGENTS.md`. Do not overwrite it or run this nested staging directory as a workspace. Compatible foreign discovery may find other skills/agents: resolve name collisions explicitly.

The eight skills use `name`/`description` YAML and Markdown wrappers. Leave them inline: no `agent`, `subagent`, model or auto-approval fields are added. On Devin skills, `allowed-tools` concerns auto-approval; it is not worker tool denial. By contrast, custom-agent `allowed-tools` is a restrictive allowlist. Eleven native flat Markdown profiles embed the existing role bodies with `allowed-tools: []`. Empty-list enforcement has not been live-tested. The directory-style `agents/<name>/AGENT.md` is another confirmed layout, not required here.

Root selects the exact `math-*` profile with `run_subagent`, supplying the complete exported packet unchanged through the actual installed schema; retrieve actual output with `read_subagent`. Do not guess argument keys from another host. Retain returned identities and failures; an interruption or missing result does not authorize redispatch. Use separate exact tasks for independent parallel work, never forward root chat, other verdicts or campaign/build history. No nesting override is supplied. Root assesses outputs and owns execution/canonical commits under [POLICY](../shared/POLICY.md).

**Model compatibility is limited:** custom profiles without `model` use the host default subagent model, which may be router/admin-selected. They do not inherit the parent model. The general built-in inherits the model but also has different tools; do not silently substitute it for a specialist. Exact parent-effort inheritance is unconfirmed. These files leave model/effort unset and add no router, automatic pin or Fusion/Adaptive setup. Before dispatch, disclose the mismatch and keep delegated operation blocked unless manual user configuration establishes compatible settings. Every shared role body, including its inheritance sentence and JSON contract, is preserved exactly. Root must establish compatible effective settings before dispatch; rewriting the role cannot repair host routing.

Custom agents are experimental, and shared codebase context is not proven mathematical blindness. No producer-bound Devin capture backend is supplied; output cannot bypass independent-review/audit/release gates. No installation, Cloud handoff, tests, builds or live host validation occurred.
